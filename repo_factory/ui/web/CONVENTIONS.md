# How the page's components are written

The page is Svelte 5 with TypeScript, built by Vite: a small shell (`App.svelte`, `src/shell/`),
the pages (`src/pages/builds`, `src/pages/settings`), a few shared parts (`src/ui/`) and pure
functions (`src/lib/`).

## Svelte 5, runes only

- `compilerOptions.runes: true`: `$state`, `$derived`, `$effect`, `$props`. Svelte 4 syntax
  (`export let`, `$:`, `on:click`) does not compile. Events are attributes: `onclick={save}`.
- TypeScript in every component, `strict` on. `npm run check` runs
  `svelte-check --fail-on-warnings`: a type error or an accessibility warning fails CI.
- No SvelteKit, no router library: the routes are hash routes, read as data (`lib/router.svelte.ts`).

## Never write HTML

- No `{@html}`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval(`,
  `new Function`, `srcdoc` or `javascript:` anywhere in `src/`. Svelte escapes every
  `{expression}`; nothing may bypass it.

## Styling: tokens only

- `../static/repo-factory.css` holds the tokens (light and dark) and the resets; `theme.js` stays
  first in `<head>`. `src/app.css` and a component's `<style>` use `var(--…)` for every colour,
  never a literal. No CSS framework, no component library.
- Svelte trims the white space at the start and end of a block's content: write a space that
  matters as a string, `{" · "}`.

## Words

- Plain words a stranger reads. The product's name comes from `lib/product.ts` only.
- A build's stages are Brief, Plan, Build, Check, Fix, Publish (`lib/stages.ts`).

## Data

- Reads are relative paths (`api/...`), cached and reactive (`lib/reads.svelte.ts`); the live
  feed (`api/stream`) marks them stale. Types come from Python (`api/types.gen.ts`, generated by
  `scripts/gen_ts.py`), with a minimal local type where the generated one has none.
- Writes to a build are registry actions through `api/act` (`api/client.ts`); a press that
  publishes, makes public or stops asks first.

## Dependencies and the build

- Development dependencies only, at exact versions, installed with `npm ci --ignore-scripts`.
  A new one needs a reason in its pull request.
- The build is one module script and its CSS from this origin (the page's policy is
  `script-src 'self'`), within the budget in `scripts/build_ui.py`.
- Tests: Vitest with jsdom, beside the file they test (`*.test.ts`; `*.svelte.test.ts` when they
  mount a component).
